# Project List

Demos are numbered in rough order of complexity — start at `01-` if you're new to Strata, and work up toward the real-world examples at the higher end. Each one is the Rust twin of the demo with the same number in [`strata-demos-dotnet`](https://github.com/datalium/strata-demos-dotnet/tree/main/demos): same story, same scenarios, the same checks where the engines agree, and a README that says where they differ.

| # | Demo | Package | Description |
|---|------|---------|-------------|
| 01 | [hello-agent](01-hello-agent) | `hello-agent` | Single-node graph: reads `name` from state, writes a `greeting`. `StateGraph` → `.compile()` → `.run(...).await` with a sync handler, nothing else. |
| 02 | [tool-calling](02-tool-calling) | `tool-calling` | An async node dispatches an `#[strata_tool]`-generated `add` tool through a `ToolRegistry` with a `ToolCallContext::from(&ctx)` built from its `NodeContext` (STRATA-SPEC-003); the tool reads its caller from it and refuses a context-free call, and the manifest leaves the context parameter out (`design/20-Tool-Dispatch-And-Registry.md`). |
| 03 | [llm-tool-calling](03-llm-tool-calling) | `llm-tool-calling` | A live model, OpenAI or a local one such as Ollama (through `datalium-strata-ai`'s `OpenAiChatClient`, no third-party SDK) decides to call the `add` tool from demo 02, and Strata's own agent loop (`Agent::<String>` + `add_agent_node`, `design/44-LLM-Integration.md`) declares it, dispatches the call through a `ToolRegistry` with the agent's id and the model's call id in the `ToolCallContext`, sends the result back and returns the answer. Requires `OPENAI_API_KEY`, or `OPENAI_BASE_URL` for a local model such as Ollama, with no key (see its README). |
| 04 | [multi-node-graph](04-multi-node-graph) | `multi-node-graph` | A linear chain (`.add_edge(...)`) feeding a conditional branch (`.add_conditional_edge(...)`) that reconverges on a shared node — `CalculateSubtotal` -> `ApplyDiscount` -> bulk/standard shipping branch -> `FormatReceipt`; both branches are run and checked. |
| 05 | [hitl-interruption](05-hitl-interruption) | `hitl-interruption` | Human-in-the-loop interruption with typed signals (STRATA-SPEC-002, `design/21-Typed-Human-Signals.md`): two wire transfers freeze at `.add_interrupt_boundary_with_reject(..., "CancelWireTransfer")` in a real SQLite file; after a simulated restart a new store lists what is waiting (`list_threads`), refuses a string override that doesn't fit an `f64` before touching the checkpoint, approves one transfer with a typed override (`ExecuteWireTransfer` reads the reviewer from `ctx.decision()`) and rejects the other onto its reject route. |
| 06 | [token-streaming](06-token-streaming) | `token-streaming` | A model node (`add_model_node`) streams a live model's answer (OpenAI, or a local one such as Ollama) through `run_streaming` as `Token` chunks, while the node gets the whole answer back as one `ChatResponse`. Then a request for a model that doesn't exist gets a real provider 4xx, which fails the node fatally: one attempt, and its `RecoveryPolicy` doesn't retry (STRATA-SPEC-001, `design/44-LLM-Integration.md`). Requires `OPENAI_API_KEY`, or `OPENAI_BASE_URL` for a local model such as Ollama, with no key (see its README). |
| 07 | [graph-validation](07-graph-validation) | `graph-validation` | A document review pipeline built twice from the same nodes: an unguarded retry loop plus a typo in an edge makes `.compile()` return `StrataError::GraphInvalid` with `STRATA_ERR_DANGLING_EDGE`, `STRATA_ERR_ORPHAN` and `STRATA_ERR_UNGUARDED_CYCLE`; guarding the retry edge and fixing the typo makes it compile and run, with a branch-and-rejoin inside the guarded loop (STRATA-SPEC-004). |
| 08 | [error-recovery](08-error-recovery) | `error-recovery` | `.add_fallible_node(...)` + `RecoveryPolicy`: a flaky payment gateway is retried with exponential backoff (`with_backoff`), a 503's retry hint (`NodeError::transient_after`) sets the wait (capped at max), the fallback reads why from `NodeContext::last_failure()`, failed attempts' partial state is rolled back, and a fatal error leaves a durable `Failed` checkpoint in SQLite that is resumed once the cause is fixed (`design/04`, `design/25`). Waits run on tokio's paused clock. |
| 09 | [cross-language-interop](09-cross-language-interop) | `cross-language-interop` | Freeze a wire-transfer graph in one runtime and resume it in the other through one shared SQLite checkpoint log: `-- freeze` here then `resume` from the .NET twin (or the reverse). Each node stamps which runtime ran it, a second resume is refused from either side, and the `strata` CLI reads the same file. All four directions verified on 0.9. Two modes: `freeze` / `resume`. |
| 10 | [parallel-fan-out](10-parallel-fan-out) | `parallel-fan-out` | `.add_parallel_group(...)` with async branches: a trip planner asks three simulated services concurrently and merges them with a reducer. On a paused tokio clock it shows exact overlap (group time = slowest branch, peak in flight 3), a merge in branch *declaration* order, group-level failure (the first failure cancels the siblings still running; a transient blip retries *all* branches, a fatal one falls back on the pre-group state), and streaming branches attributed to `GatherInfo/<branch>` (`design/14-Parallel-Execution.md`). Options and joins are demo 17. |
| 11 | [backpressure](11-backpressure) | `backpressure` | An async flood node emits 20 000 tokens with `emit_token(..).await` through `run_streaming` against three bad consumers, proving the 1024-chunk channel *pauses* the node instead of dropping tokens: a stalled consumer freezes it at exactly 1023 tokens (plus the engine's `NodeStart` = 1024 queued chunks) with nothing lost once it drains; a slow consumer never lets it get more than 1024 tokens ahead; an abandoned one is released by dropping the receiver (`ChannelClosed`) or by cancelling the run, which ends `Cancelled` with a resumable checkpoint (STRATA-SPEC-001, `design/17-Async-Execution.md`). |
| 12 | [pluggable-storage](12-pluggable-storage) | `pluggable-storage` | One graph, one scenario, four storage backends — in-memory, SQLite, **Postgres** and **Redis** — through the same code: freeze a wire-transfer graph, drop every connection, resume from a fresh one, read a chat history back. Also the 0.9 store constructors (connect, migrate, retries), concurrent writers, delta checkpoints written by one store and read whole by another without them (`design/41-Checkpoint-Efficiency.md`), and a cross-runtime hand-off through Postgres or Redis with the .NET twin. Requires Docker (`docker compose up -d --wait`). Modes: matrix (default), `freeze` / `resume`. |
| 13 | [subgraph-composition](13-subgraph-composition) | `subgraph-composition` | `.add_subgraph(...)`: a support desk whose `Triage` supervisor routes tickets to specialist agents that are *compiled graphs of their own*, three levels deep. Recovery composes across levels; a fatal error two levels down leaves a `Failed` checkpoint nesting each child's, and a resume re-enters at the failed node; a boundary inside a child freezes the whole desk, the typed override lands in the child's state and the decision is seen only at the child's level; the exported definition carries every child's graph (`design/15`, `design/16`, `design/22`). |
| 14 | [graph-ci-gate](14-graph-ci-gate) | `graph-ci-gate` | `strata graph validate` as a CI gate: seven graphs built in code are exported with `StateGraph::to_definition()` (which, unlike `.compile()`, accepts a broken graph) and checked as a folder by the real `strata` binary. A failing pull request (exit 1) with the CLI and `.compile()` agreeing on every diagnostic, the trap of exporting a compiled graph's definition, an interrupt boundary with a reject route in the file (`"interrupt"`, `1.6.0`, `strata graph view`), the fix (exit 0), and what a gate that can't check does (exit 2, including a hand-edited boundary). All seven files are byte-identical with the .NET twin's (STRATA-SPEC-004, `design/48-Boundaries-In-Definitions.md`). |
| 15 | [async-and-cancellation](15-async-and-cancellation) | `async-and-cancellation` | Async handlers and what `NodeContext` tells them (thread, qualified path, attempt, run id, metadata) with run-level inputs in `RunConfig`; `set_timeout` turning a hung attempt into a transient failure a retry recovers; a sync handler on tokio's blocking pool abandoned, its late side effect still landing; cancellation by token and by deadline as a resumable `Cancelled` checkpoint that a resume re-enters at the stopped node only; and (Rust only) inline sync nodes. Timeouts run on a paused tokio clock (`design/17`, `design/39`). |
| 16 | [loop-circuit-breaker](16-loop-circuit-breaker) | `loop-circuit-breaker` | The loop circuit breaker (`CompileOptions::with_max_node_hops`): a scheduling agent that never converges is refused before hop 13 with `StrataError::HopLimitExceeded` and a `Failed` checkpoint (`error_kind = hop_limit`, `strata.hops`). Retries aren't hops, the count survives interrupts and resumes by a freshly built graph, and `RunConfig::with_max_node_hops` raises or lowers the limit for one run (`design/24-Loop-Circuit-Breaker.md`). |
| 17 | [parallel-joins](17-parallel-joins) | `parallel-joins` | Parallel group options (`design/26-Parallel-Group-Controls-And-Joins.md`): three carriers quote for a parcel under `Join::first_success()` (losers cancelled with `LostRace`), `Join::first_matching(..).described(..)` (with a `keep_succeeded` fallback to every answer), `Join::quorum(2)` and a `with_max_concurrency(1)` failover chain; `JoinDecided` and `BranchCompleted`'s reason say who won and why the rest stopped. Also when an unmet join fails transiently or fatally, and an `add_parallel_group_with_outcomes` tracking board with a branch timeout, a concurrency limit and `keep_succeeded` on tokio's paused clock. |
| 18 | [map-fan-out](18-map-fan-out) | `map-fan-out` | `.add_map` / `.add_map_with` / `.add_map_with_outcomes` (`design/27-Map-Fan-Out.md`): an invoice audit runs a compiled child graph once per line, keyed by line id (`AuditLines/<line>/<node>`), at most 8 at a time by default (never unbounded). Duplicate, `/`-containing or empty keys, or more than `max_items`, fail the map fatally before anything starts; a failing line's fatal or transient kind (with its retry hint) becomes the map's, and a retried map re-runs every line; an outcomes reducer with `keep_succeeded()`; `.compile()` refusing a child with an interrupt boundary at any depth. |
| 19 | [waits-and-timers](19-waits-and-timers) | `waits-and-timers` | Event waits, durable timers and ending a thread (`design/28`, `29`, `42`): orders that wait for a payment `signal`, a fraud review that times out to its `on_timeout` route, a pickup timer woken by `wake_due(store, now)` or by your own `resume_streaming(.., LevelSignals::due_at(now))`, `end_with`, and a `timed_out` end, all on a SQLite file with an explicit `now`. |
| 20 | [durable-execution](20-durable-execution) | `durable-execution` | `CheckpointPolicy::EveryNode` and a real crash: the demo re-launches itself as a worker process and kills it inside `Charge`, leaving a `running` thread in SQLite with its lease unreleased. `resume` refuses it, `recover_stale` skips it while the dead worker's lease is live and recovers it once it expires (explicit `now`), and at-least-once execution re-runs `Charge` with the same `idempotency_key()` and `is_recovery()`, so a deduplicating gateway charges once; `recoveries_of` and the `Recovered` event (`design/33-Durable-Execution.md`). |

## Adding a demo

1. `cargo new demos/NN-demo-name` from the repo root — note Cargo package names can't start with a digit, so set `name` in that demo's `Cargo.toml` to something like `demo-name` (folder keeps the `NN-` prefix, package name doesn't need it)
2. Add `"demos/NN-demo-name"` to `members` in the root `Cargo.toml`
3. Depend on core crates via `{ workspace = true }` (see root [README.md](../README.md#dependencies-on-strata))
4. Add a row to the table above
